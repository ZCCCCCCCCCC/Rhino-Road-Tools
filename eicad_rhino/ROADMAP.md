# 市政道路 BIM 辅助建模工具集规划

## 1. 定位

本项目是一个以 Rhino 8 / Python 3 为运行平台、以路线为基线的市政基础设施 BIM 辅助建模工具集。

工具集的目标不是替代道路、桥梁、隧道等专业设计计算软件，也不是将 EICAD 文件一次性转换为成品模型。它的目标是：

- 将经过设计确认的路线数据稳定导入 Rhino。
- 使用项目自定义的参数、模板和构件库，快速生成可编辑的三维 BIM 几何。
- 让道路、桥梁、隧道、标线、交安和市政附属设施共享路线、桩号、坐标和构件元数据。
- 支持参数调整后的局部更新、质量校核、工程量辅助统计和后续交付。

核心原则是“路线数据只作为基线，专业模型由本工具集自主生成”。

## 2. 范围与边界

### 2.1 目标专业

| 专业 | 覆盖对象 |
| --- | --- |
| 道路 | 路面、人行道、非机动车道、路缘石、中分带、结构层、边坡、排水沟 |
| 标线 | 车道线、边线、导向箭头、文字、斑马线、停止线、导流区 |
| 交安 | 护栏、隔离墩、防撞墙、标志牌、信号灯、轮廓标、道钉、减速设施 |
| 桥梁 | 桥面、梁体、桥墩、盖梁、台帽、桥台、支座、伸缩缝、栏杆、防撞墙 |
| 隧道 | 洞门、开挖轮廓、初支、二衬、仰拱、路面、排水沟、电缆沟、预留孔洞 |
| 市政附属 | 雨污水管线、检查井、边沟、雨水口、路灯、绿化带、综合管线占位 |
| 质量与交付 | 净空检查、桩号高程校核、构件统计、工程量辅助、DWG/IFC/表格导出 |

### 2.2 明确不替代的工作

- 不替代结构受力计算、配筋设计、交通组织设计、信号配时和专业规范审查。
- 不把来源不明或不完整的 EICAD 横断面数据直接转成 BIM 成果。
- 不在没有参数来源或人工确认的情况下自动生成桥梁和隧道结构尺寸。
- 不以 NURBS 拟合替代需要精确桩号控制的线路和构件定位。

## 3. 当前基线

当前已完成“路线导入 + 断面控制线”基础能力。

| 模块 | 当前状态 | 说明 |
| --- | --- | --- |
| EICAD 平面解析 | 已完成 | ICD 优先，兼容 JD；支持直圆直连、无圆曲线折点等实际导出形式 |
| 纵断面与桩号 | 已完成 | 读取 SQX、ST，生成三维中心线和关键桩号点 |
| Rhino 路线导入 | 已完成 | 支持单条、多选、全部导入、递归子文件夹扫描和固定 XY 交换 |
| 坐标元数据 | 已完成 | 记录来源、比例、XY 交换、原点偏移和桩号范围 |
| 参数化断面核心 | 已完成 | 支持非对称断面、中分带、参考线偏距、横坡和桩号区间 |
| Eto 断面编辑器 | 已完成 | 推荐板块可视化编辑器，支持断面预览、板块顺序、宽度、横坡、竖向变化和桩号区间；保留控制点高级编辑器 |
| 控制线生成 | 已完成 | 输出横断面线和命名纵向控制线，不生成路面实体 |
| 道路曲面与实体 | 未开始 | 下一优先级模块 |

## 4. 总体架构

```text
EICAD ICD/JD + SQX/ST
        |
        v
路线计算核心 eicad_import/eicad_alignment.py
        |
        v
Rhino 路线对象 + 路线元数据
        |
        +-------------------------------+
        |                               |
        v                               v
断面/构件 JSON                    专业布置参数 JSON
        |                               |
        v                               v
道路、桥梁、隧道、标线交安生成器
        |
        v
Rhino 几何 + 统一用户文本 + 图层体系
        |
        v
更新、校核、统计、导出
```

系统分为三层：

1. **基线与计算层**：路线、桩号、坐标、纵断面、横断面参数和空间定位计算。该层不依赖 Rhino，应可由普通 Python 回归测试覆盖。
2. **专业构件层**：道路、桥梁、隧道、标线和交安的参数模板、布置规则、构件库与 JSON 定义。
3. **Rhino 适配层**：图层、对象创建、用户文本、替换更新、选择交互、可视化和导出。

## 5. 统一数据与对象规范

### 5.1 路线基线

每条已导入路线对象至少记录以下 Rhino 用户文本：

| 字段 | 含义 |
| --- | --- |
| `eicad_route` | 路线名称 |
| `eicad_source_path` | ICD/JD 来源路径 |
| `eicad_horizontal_source` | ICD 或 JD |
| `eicad_station_start` / `eicad_station_end` | 路线桩号范围 |
| `eicad_coordinate_scale` | Rhino 坐标比例 |
| `eicad_swap_xy` | 是否交换 XY |
| `eicad_origin_offset` | Rhino 局部坐标原点偏移 |

### 5.2 专业构件元数据

所有脚本生成的对象都应补充以下通用字段：

| 字段 | 含义 |
| --- | --- |
| `discipline` | `road`、`bridge`、`tunnel`、`traffic`、`utility` 等 |
| `component_type` | 构件类型，例如 `pavement`、`guardrail`、`pier` |
| `component_id` | 稳定、可追踪的唯一 ID |
| `eicad_route` | 所属路线 |
| `station_start` / `station_end` | 构件控制桩号范围 |
| `template_name` | 所使用的模板名称 |
| `definition_path` | JSON 参数文件来源 |
| `generator` / `generator_version` | 生成脚本及版本 |

更新脚本必须按 `component_id` 或“路线 + 模板 + 桩号范围”识别自身对象，只替换自己的产物，不删除其他专业对象。

### 5.3 图层规范

建议统一图层路径：

```text
EICAD::<路线>::Centerline
EICAD::<路线>::Stations
EICAD::<路线>::Road::<走廊>::<构件>
EICAD::<路线>::Traffic::<设施类型>
EICAD::<路线>::Bridge::<桥梁名称>::<构件>
EICAD::<路线>::Tunnel::<隧道名称>::<构件>
EICAD::<路线>::Utility::<系统>::<构件>
```

## 6. 参数文件规范

参数文件统一采用 UTF-8 JSON，避免将工程规则写死在 Python 脚本中。

### 6.1 走廊断面定义

走廊 JSON 已支持：

- 多个典型断面模板。
- 从左到右的可视化道路板块，可自动展开为控制点。
- 任意顺序的断面控制点。
- 控制点的相对偏距、相对高程或与前点横坡。
- 按桩号区间绑定模板。
- 路线参考偏距和参考高程偏移。
- 中分带、分离式路基、非对称路幅和路线偏置。

正偏距定义为行进方向左侧。点表顺序决定横坡计算顺序，不能默认左右对称。

### 6.2 构件模板定义

后续桥梁、隧道和交安设施应采用同样的结构：

```text
项目定义
  -> 构件模板
  -> 布置区间或布置规则
  -> 生成器参数
```

例如护栏模板应定义截面、材料、立柱间距、端部类型和适用区间；桥墩模板应定义墩型、截面、墩高、盖梁和支座参数。

## 7. 阶段路线图

### 阶段 0：平台规范与稳定性

目标：让所有后续脚本具备一致的数据边界、更新方式和回归基础。

- 完善项目级配置文件与图层配置。
- 建立统一的对象元数据帮助函数。
- 建立 JSON 版本迁移机制。
- 建立构件 ID 和安全替换机制。
- 完善 Git 工作流、中文提交说明和变更日志。
- 为每个计算核心增加独立回归测试。

验收：任意生成器均可重复执行且不产生重复对象；参数文件和生成对象可相互追溯。

### 阶段 1：道路走廊闭环

目标：从路线和断面参数生成完整道路 BIM 几何。

#### 1.1 道路曲面生成

新增 `rhino_build_road_surfaces_py3.py`：

- 按命名纵向控制线生成车行道、人行道、非机动车道、中分带和路肩曲面。
- 支持不同模板区间间的断面过渡。
- 保留控制线，不以删除控制线换取曲面结果。
- 生成对象与走廊 JSON 建立追溯关系。

#### 1.2 道路结构层

- 根据路面控制曲面和厚度规则生成基层、底基层、垫层等实体或封闭体。
- 支持横向不同构件的厚度和材料。
- 支持人行道铺装、盲道、路缘石、树池和分隔带。

#### 1.3 变断面与超高

- 模板按桩号区间切换。
- 加宽、收窄、渐变段和匝道分合流。
- 横坡或超高按桩号线性/分段变化。
- 断面变化处自动加密采样。

验收：对一条路线修改断面参数后，可重新生成指定走廊，且边线、曲面和结构层同步更新。

### 阶段 2：标线与交安设施

目标：以道路边线、车道线和桩号为基准完成交通附属设施辅助建模。

#### 2.1 标线

- 车道分界线、边线、导流线、停止线、斑马线、导向箭头和文字。
- 支持实线、虚线、双线、颜色、宽度、间隔和桩号区间。
- 标线贴附到指定道路曲面，避免悬空或穿透。
- 交叉口和渠化区采用局部平面/曲线辅助布置。

#### 2.2 交安

- 波形梁护栏、混凝土护栏、隔离墩、隔离栅。
- 标志牌、标志杆、信号灯、灯杆、轮廓标、道钉和减速设施。
- 支持沿线间距布置、指定桩号布置、转角/端头构件和避让规则。
- 支持构件库与参数化截面，减少重复手工建模。

验收：通过 JSON 或 Eto 表单配置后，可在指定路线、侧别和桩号范围内重复生成、更新和统计交安对象。

### 阶段 3：桥梁辅助建模

目标：以道路路线和桥跨布置为基线完成常见桥梁上部、下部和附属构件建模。

#### 3.1 桥梁总体与桥面

- 桥梁区间、桥跨、桥面宽度和横坡定义。
- 桥面板、防撞墙、栏杆、人行道、泄水孔和铺装层。
- 与道路走廊的高程、横坡和衔接控制线关联。

#### 3.2 下部结构

- 桥墩、盖梁、台帽、桥台、承台、桩基占位。
- 常见墩型和桥台模板。
- 支座、垫石、伸缩缝和支撑线布置。

#### 3.3 上部结构

- 预制梁、箱梁、板梁等常见上部构件的参数化占位或构件级模型。
- 横隔梁、湿接缝和桥面附属构件。

验收：输入桥跨和模板参数后，可生成与路线和道路横断面一致的桥梁总体模型，并可单独更新某跨或某墩。

### 阶段 4：隧道辅助建模

目标：以路线和隧道断面定义生成隧道主体与常见附属结构。

- 洞门、明洞、暗洞区间定义。
- 开挖轮廓、初期支护、二次衬砌、仰拱、填充层和路面。
- 排水沟、电缆沟、消防管沟、预留孔洞和设备基座。
- 隧道内标线、照明、标志和风机等机电占位接口。
- 断面变化、加宽段和洞口过渡。

验收：可针对单条路线和指定隧道区间生成分层隧道模型，并保留可审查断面控制线。

### 阶段 5：市政附属与综合协调

目标：扩展道路工程中的常见附属专业，并形成空间协调能力。

- 雨水、污水、给水、电力、通信等管线占位。
- 检查井、雨水口、边沟、截水沟和排水口。
- 路灯、绿化带、树池和小型附属构筑物。
- 管线与道路、桥梁、隧道的净距和碰撞检查。

验收：可基于路线和道路边界布置常见市政附属对象，并输出对象数量、桩号和高程信息。

### 阶段 6：校核、统计与交付

目标：让模型具备项目交付前的可检查性和可追溯性。

- 路线桩号、高程、横向偏距和超高检查。
- 道路、桥梁、隧道、管线之间的碰撞和净空辅助检查。
- 构件数量、长度、面积、体积和材料分类统计。
- 图层、名称、用户文本和 JSON 来源完整性检查。
- DWG 图层整理、IFC 属性映射、CSV/XLSX 工程量辅助导出。

验收：可形成可复现的检查报告和构件统计结果，并能定位问题到路线、桩号、构件 ID 和参数文件。

## 8. 用户工作流

### 8.1 道路工作流

1. 使用 `eicad_import/rhino_import_eicad_multi_py3.py` 导入路线。
2. 使用 `corridor_modeling/rhino_corridor_block_editor_py3.py` 创建或打开走廊 JSON；特殊不规则断面可使用 `corridor_modeling/rhino_corridor_editor_py3.py`。
3. 编辑模板、断面点和桩号区间。
4. 生成断面线与纵向控制线。
5. 生成道路曲面和结构层。
6. 在道路曲面上布置标线和交安设施。
7. 运行校核与统计。

### 8.2 桥梁与隧道工作流

1. 选择关联路线和桥梁/隧道桩号区间。
2. 选择专业模板并填写项目参数。
3. 生成总体控制线和关键断面。
4. 生成专业构件。
5. 复核与道路、交安、管线的连接关系。
6. 按构件 ID 局部更新或重建。

## 9. 质量要求

### 9.1 几何要求

- 任何路线驱动对象必须能够追溯到桩号。
- 曲线采样容差必须可配置并记录到用户文本。
- 桥梁、隧道和道路构件的接口处必须保留控制线或基准面。
- 不允许使用未声明的硬编码坐标或设计尺寸。

### 9.2 稳定性要求

- 所有独立计算模块应可在 Rhino 外执行单元/回归测试。
- 生成脚本重复运行不得积累重复对象。
- JSON 参数不合法时，应在创建 Rhino 对象前给出明确错误。
- 任何自动外推、数据缺失或不一致都应在 Rhino 命令历史中给出警告。

### 9.3 文档要求

- 每个脚本在 README 或对应模块文档中说明输入、输出、坐标、参数和限制。
- 每个 JSON 版本都有字段说明和兼容策略。
- 每次 Git 提交使用中文说明，描述功能、修复或行为变化。

## 10. Git 与版本管理

- Git 仓库范围为 `eicad_rhino` 脚本与文档目录，不默认纳入外部工程资料和测试成果。
- Python 缓存、虚拟环境和编辑器临时文件由 `.gitignore` 排除。
- 每次提交使用中文提交说明。
- 功能开发建议按“数据模型 -> 计算验证 -> Rhino 适配 -> UI -> 回归测试 -> 文档”顺序完成。
- 影响对象几何或参数含义的修改，必须同步更新回归测试与 README。

## 11. 近期优先级

下一开发模块为 `rhino_build_road_surfaces_py3.py`，完成道路走廊的第一轮闭环：

1. 从当前 `Breaklines` 读取命名纵向控制线。
2. 依据相邻控制线生成道路曲面。
3. 为车行道、人行道、中分带等构件分层输出。
4. 保留原控制线并写入构件元数据。
5. 支持重复生成时仅替换当前走廊的路面对象。

道路曲面稳定后，再进入标线交安模块；桥梁和隧道模块共享同一条路线、参数文件、构件元数据和更新机制。
